applyTo: '**'

Orientações gerais de codificação

  • Use o padrão PSR-12 para formatação e K&R para chaves ({}).
  • Use nomes claros e autoexplicativos, evitando abreviações desnecessárias.
  • Escreva código coeso, com responsabilidade única por classe (SRP).
  • Siga os princípios SOLID e Clean Code.
  • Evite código duplicado, condições aninhadas profundas e efeitos colaterais.
  • Prefira retornos antecipados (early return) sempre que aplicável.
  • Use tipagem explícita e funções puras.

Organização do código

  • Agrupe funções e métodos com responsabilidades similares.
  • Separe claramente lógica de negócio, apresentação e dados.
  • Use estrutura em camadas: Controllers, Services, Repositories, etc.
  • Evite lógica de banco nos controladores.

Orientação a Objetos (OOP)

  • Prefira composição a herança.
  • Use injeção de dependência via construtor.
  • Mantenha classes pequenas e coesas.
  • Evite "God objects".
  • Use readonly e enum (PHP 8.1+).

Backend / APIs

  • Siga padrão RESTful (GET, POST, PUT, DELETE).
  • Valide dados antes de processar.
  • Retorne JSON estruturado com status code adequado.
  • Use DTOs para entrada e saída.

Testabilidade

  • Prefira funções puras e baixo acoplamento.
  • Use injeção ou fábricas, evite new direto.
  • Não dependa diretamente de $_POST, $_GET, etc.

Segurança

  • Nunca exponha exceções ao usuário.
  • Não armazene senhas em texto puro.
  • Sanitize saídas com htmlspecialchars.
  • Use prepared statements.
  • Nunca registre dados sensíveis em logs.

Projeto e dependências

  • Use PSR-4 e organize bem o composer.json.
  • Prefira pacotes bem mantidos e versionados.
  • Versione o composer.lock.

Convenções adicionais

  • Use match em vez de if/elseif longos.
  • Capture exceções específicas.
